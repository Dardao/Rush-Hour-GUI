# Rush Hour — Neural Array Lab v0.2.11

macOS 로컬 연구용 NumPy/PySide6 GUI. 전체 2500개 퍼즐의 역할을 고정하고,
차량 순서 증강·성공 replay·curriculum을 함께 적용합니다.
100개 보드와 세 그래프를 표시합니다. GitHub에는 자동 업로드하지 않습니다.

## 실행

Python 3.10 이상이 필요하며 Python 3.12 환경에서 검증했습니다.
macOS에서 `python3`가 3.9라면 Python 3.12 실행 파일로 가상환경을 만드세요.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install --no-compile -r requirements.txt
python main.py
```

`--no-compile`은 PySide6 Android 템플릿의 설치 중 사전 컴파일 오류를 피합니다.
다음 실행에는 가상환경 활성화 후 `python main.py`만 필요합니다.
Apple Silicon/Intel Mac의 실제 실행은 사용자 환경에서 확인해야 합니다.

## 사용 방법

1. `APK 가져오기`로 로컬 APK의 2500개 초기 배치를 불러옵니다. 기존 Minimum possible 매핑을 유지합니다.
2. 전체/학습/검증/테스트 필터 및 **100개 단위 슬라이더**로 이동합니다. 전체는 25페이지입니다.
3. `강화학습`은 현재 페이지와 무관하게 전체 학습 집합을 사용합니다.
   한 epoch에서 curriculum 대상 학습 문제를 무작위 순서로 모두 한 번씩 방문하며 100개씩 처리합니다.
4. 성공 replay 후 가중치를 고정하고 전체 학습+검증을 초기 배치부터 greedy 평가합니다.
   테스트는 자동 평가에서 제외합니다. **검증·테스트는 가중치 업데이트나 replay에 들어가지 않습니다.**
5. 학습 중에도 슬라이더와 필터를 사용할 수 있습니다. 원래 차량 순서·색상으로 현재 단계를 표시하며
   먼저 처리한 문제의 최종 상태도 유지됩니다. 단계/epoch가 바뀌면 보드 상태를 초기화합니다.
   `ready`는 아직 처리 전이거나 그 단계의 대상이 아닌 문제입니다.
6. `현재 100개 추론`은 화면 문제를, `테스트 평가`는 테스트 252개 전체를 고정 모델로 평가합니다.
   테스트 결과는 별도 표시·로그이며 학습 그래프에 섞지 않습니다. 추론 간격 설정은 수동 평가에만 적용됩니다.
7. 보드를 클릭하면 확대 화면, 행동 점수와 value를 확인합니다. 학습 중 상세 점수는 최근 완료 epoch의 모델 기준입니다.
8. `저장`/`불러오기`는 기존 v2 NPZ 가중치와 Adam 상태를 보존합니다. 기존 RL 모델도 로드할 수 있습니다.
   replay buffer, curriculum/epsilon 진행, RNG, 그래프 이력은 저장하지 않습니다.
   새 학습 실행은 현재 가중치에서 시작하되 replay와 일정은 새로 시작합니다.

슬라이더는 모니터 위치만 바꿉니다. 학습 문제 선택, RNG, 업데이트, 그래프 분모에는 영향을 주지 않습니다.
화면에는 100개만 그리며 worker는 약 80ms마다 현재 처리 batch의 상태를 전달합니다.
`정지`는 다음 행동/업데이트 단위에서 처리하고 완료된 가중치를 보존합니다. 미완료 epoch 지표는 기록하지 않습니다.

## 전체 분할과 epoch 정의

차량 방향·길이·lane·목표 여부의 정렬된 topology를 SHA-256으로 해시하고 mod 10을 적용합니다.
버킷 0=validation, 1=test, 나머지=train입니다. 위치·차량 ID 순서와 무관하며 동일 topology가 분할을 넘지 않습니다.
정확한 80/10/10 수를 강제하지 않으며, 모드별 층화는 별도로 적용하지 않습니다.

| 구분 | 실제 APK 개수 | 매 epoch 사용 |
| --- | ---: | --- |
| 학습 | 2034 | curriculum 해당 문제 전부 학습 → 전체 2034개 greedy 평가 |
| 검증 | 214 | 전체 214개 greedy 평가만 |
| 테스트 | 252 | 별도 테스트 평가 버튼에서만 사용 |

한 epoch는 **해당 curriculum 학습 집합 한 순회 + 성공 replay 최대 30경로 + 학습/검증 전체 평가**입니다.
이전 버전의 88문제 epoch와 계산량이 다릅니다. 전체 난이도 단계에서는 2034개 학습 episode와 2248개 평가가 실행됩니다.
검증 결과로 자동 재학습하거나 replay에 추가하지 않습니다. 테스트를 보고 설정을 반복 조정하면 독립 최종 평가의 의미는 줄어듭니다.

## 네 가지 변경

- **전역 학습/검증/테스트 분할**: 화면 100개와 실제 학습 대상을 분리했습니다.
- **차량 순서 증강**: 빨간차는 0번을 유지하고 일반 차량의 슬롯을 episode마다 섞습니다.
  입력과 행동 번호를 함께 변환하며 GUI 상태·경로는 원래 순서로 복원합니다. replay 때도 다시 섞습니다.
- **성공 replay**: 학습 탐험으로 실제 성공한 경로만 저장합니다. 문제당 누적 보상이 가장 좋은 1경로,
  최대 500문제의 buffer이며 개선된 새 기록을 최신으로 두고 용량 초과 시 오래된 기록을 제거합니다.
  epoch당 최대 30경로를 무작위 비복원 추출합니다. APK 정답 수순을 사용하지 않습니다.
- **누적 curriculum**: 설정 epoch의 첫 25%는 Minimum possible ≤25, 다음 25%는 ≤35,
  다음 25%는 ≤45, 마지막 25%는 전체입니다. 쉬운 문제도 후반 학습에 계속 포함됩니다.
  조건에 맞는 문제가 전혀 없으면 전체 train으로 대체하고 로그에 표시합니다. 1 epoch 설정은 전체 단계입니다.

Minimum possible은 이번 버전부터 **curriculum 대상 선정**에만 추가로 사용합니다.
정책 입력, 보상, replay의 수익 표적에는 넣지 않습니다. 정답 행동 경로도 로드하지 않습니다.

## 학습과 보상

기존 epsilon-greedy V-trace actor-critic을 유지합니다. gamma=.99, n-step=16,
엔트로피=.02, Adam lr=.0003, gradient norm clip=1입니다.
Epsilon은 새 실행 시작 1.00에서 설정 epoch의 앞 80% 동안 .05로 감소하고 이후 유지합니다.
평가는 epsilon=0이며 성공·반복 배치·300 행동 중 먼저 도달한 조건에서 종료합니다.
학습은 반복 배치에 벌점을 주며 최대 300 행동까지 계속합니다.

| 항목 | 보상 |
| --- | --- |
| 이동 | −0.01 × 이동 칸 수 |
| 반복 배치 | 추가 −0.03 |
| 성공 | +1, 마지막 이동 및 자동 탈출 거리 비용 포함 |

빨간차 오른쪽 길이 비면 성공입니다. GUI는 빨간차가 밖으로 나가는 동작을 표시하고,
출구까지 거리+통과 1칸을 moves와 보상에 포함합니다. Maximum reward=1−.01×Minimum possible입니다.

Replay는 편향된 성공 표본을 fresh V-trace 경험처럼 취급하지 않습니다.
별도의 **positive-advantage self-imitation** 보조 업데이트입니다.
실제로 관측한 할인 수익 G와 현재 value V로 advantage=max(G−V,0)을 계산하고,
actor에는 이 양수 advantage만, critic에는 max(G,V)를 목표로 넣습니다.
따라서 좋은 결과의 행동 확률과 낮게 예측한 value를 올리며, lr=.0001, entropy=0,
batch 최대 256 전이입니다. 실제 성능 개선은 별도 장기 비교가 필요합니다.
좋은 과거 행동을 다시 학습하는 접근은 [Self-Imitation Learning](https://proceedings.mlr.press/v80/oh18b.html)을 참고했습니다.
여기서는 성공 경로 제한, 문제별 1경로 보관, Huber critic을 사용하는 변형입니다.

## 그래프와 로그

- Solve success: 현재 curriculum의 Train explore / 전체 train의 Train greedy / 전체 validation의 Val greedy.
  탐험 대상 난이도가 단계별로 바뀌므로 explore 곡선은 단계 변화와 함께 읽어야 합니다.
- RL episode reward: 그 epoch의 **새 탐험 episode** 누적 보상 평균입니다. replay·평가 보상을 합산하지 않습니다.
- Efficiency: **전체 학습+검증 2248개 greedy 평가 평균**, 테스트 제외. 성공은 minimum/actual moves, 실패는 0.
  페이지 변경과 무관한 고정 분모입니다. 1을 넘는 원비율은 숨기지 않고 로그와 축에 반영합니다.
- 세 그래프는 위쪽 한 줄 범례, 같은 플롯 높이, 기존 그래프 영역을 사용합니다.
- `runs/rl-*.jsonl` 첫 행은 split manifest이며 이후 완료 epoch별 지표, curriculum, replay 수,
  실제 학습/평가 문제명, 문제별 moves/Efficiency를 기록합니다.
- `runs/test-*.json`은 수동 테스트 결과입니다. 반복 테스트에 대한 독립성은 사용자가 관리해야 합니다.

네트워크는 224→128→64→141 MLP를 유지합니다. 5·6·7번 후속 논의(학습 greedy 안정성 분석,
관계 기반 신경망, 탐색 보조)는 이번 변경에 포함하지 않았습니다.

- solved 시 빨간차가 오른쪽으로 사라지는 0.55초 애니메이션을 실행합니다. 화면과 카운터를 위한 자동 마무리이며 추가 RL 행동/보상은 만들지 않습니다.
- 최대 300은 에피소드의 행동 횟수입니다. 칸 수로 표시하는 moves는 300보다 클 수 있습니다.
- 길 확보 시 성공 판정, 현재 페이지 학습, 학습/검증 단계 분리, 참조해를 쓰지 않는 강화학습은 유지합니다.
- Minimum possible은 표시용 메타데이터이며 정책 입력, 보상, 최적화에 사용하지 않습니다.
- 이전 버전의 moves는 행동 횟수였으므로 숫자를 직접 비교하지 마세요.

## v0.2.5 — 칸당 보상 및 실시간 보상 표시

- 처음부터 길이 열린 문제는 자동 탈출 비용을 뺀 성공 보상을 표시하지만 학습 전이는 생성하지 않습니다.
- Reward는 가장 최근 행동의 보상, Total reward는 이번 시도의 할인 없는 누적 보상입니다.
- 학습/검증 단계와 추론 재생, 상세 창에서 표시합니다. 단계가 끝난 문제의 값은 유지되며 새 epoch/페이지에서 초기화합니다.
- 할인율 gamma=0.99는 행동마다 적용하며 기존처럼 학습 목표에만 사용합니다.
- 그래프는 학습 문제의 누적 보상 평균입니다. 검증 경험은 가중치 업데이트에서 제외합니다.
- Minimum possible은 학습에 사용하지 않습니다. 최대 300회 행동 제한 유지.
- 보상 정의가 바뀌었으므로 이전 버전의 보상 그래프와 직접 비교하지 마세요.

## v0.2.7 — 학습 탐험 후 전체 greedy 평가

각 epoch는 두 단계로 진행됩니다.
1. 현재 페이지의 학습 문제만 확률적 탐험으로 가중치를 갱신. 검증 문제는 대기.
2. 학습 종료 가중치의 고정 복사본으로 현재 페이지의 모든 문제를 초기 배치부터 greedy 평가. 학습/검증 모두 반복 배치 또는 최대 300회에서 종료. 성공 시 종료.

성공률 두 곡선은 두 번째 단계의 Train greedy / Val greedy입니다.
보상 곡선은 첫 번째 단계의 학습 탐험 평균 누적 보상입니다. 화면의 평가 보상과는 다를 수 있습니다.
로그는 탐험 성공 수와 greedy 성공 수를 별도로 보관합니다.
학습/검증의 실제 개수는 현재 페이지의 기존 분할에 따릅니다.
이 버전은 평가 조건을 일치시키며 일반화 개선 알고리즘은 추가하지 않았습니다.

## v0.2.8 — 세 그래프와 Efficiency

기존 그래프 영역의 폭을 세 그래프가 나눠 사용합니다. 가중치 영역과 상단 높이는 유지합니다.
- Solve success: Train explore / Train greedy / Val greedy 세 꺾은선.
- RL episode reward: 학습 탐험 평균 누적 보상.
- Efficiency: epoch 종료 greedy 평가의 현재 페이지 전체 평균. 성공 시 Minimum possible / actual moves, 실패 시 0. actual moves는 자동 탈출 비용까지 포함한 화면 이동 칸 수.
- 정상 기준 범위는 0~1이며 실패를 포함하므로 평균은 0일 수 있습니다. 기준보다 짧은 성공으로 1을 넘는 경우는 임의로 자르지 않고 원비율을 기록합니다. 필요 시 축이 확장됩니다.
- 로그에 문제 순서별 actual moves, Efficiency, 원비율 및 1 초과 개수를 저장합니다.
- 기준값이 없는 성공 문제는 평균을 해당 없음으로 표시합니다. APK 2,500개는 기준값이 있습니다.
- 기존 선만 표시하는 스타일 유지. 학습 알고리즘과 보상은 변경하지 않았습니다.

## v0.2.9 — epsilon-greedy

학습 행동은 확률 epsilon으로 합법적인 행동 중 균등 무작위 선택, 나머지는 최고 정책 점수 행동 선택입니다. 무작위 분기에서도 최고 점수 행동이 선택될 수 있습니다.
실행 시작 epsilon=1.00, 설정 epoch의 앞 80% 동안 선형으로 0.05까지 감소, 이후 유지. 300 epoch이면 epoch 1=1.00, epoch 240~300=0.05. 1 epoch 실행은 1.00입니다. 새 학습 실행마다 스케줄은 리셋하며 checkpoint 재개 시에도 새 스케줄입니다. UI와 epoch 로그에 epsilon을 기록합니다.
평가는 epsilon=0, 최고 점수 행동 선택, 반복 배치 종료. 학습/검증 경험 분리 유지.

기존 on-policy A2C에 행동 선택만 바꾸지 않고 V-trace 보정을 적용했습니다. 최대 16-step chunk 동안 수집한 행동에 mu(a|s)=epsilon/N+(1-epsilon)I(a=argmax)를 기록합니다. target policy는 기존 masked softmax, rho와 c는 min(1,pi/mu), gamma=0.99. V-trace 가치 표적과 rho*(r+gamma*v_next-V) 정책 advantage를 사용합니다. 엔트로피 계수 0.02 유지. gradient clipping 및 Adam 유지. 클리핑은 분산을 제한하지만 편향이 있으며 개선을 보장하지 않습니다.
참고: https://proceedings.mlr.press/v80/espeholt18a.html

이전 RL checkpoint의 네트워크 형태는 같아 로드할 수 있지만 epsilon 진행 상태는 저장되지 않습니다. 정답 수순이나 Minimum possible을 학습 표적으로 사용하지 않습니다.
장기 해결률 향상은 아직 검증하지 않았습니다.
