# Rush Hour — Neural Array Lab v0.2.4

macOS 로컬 연구용 GUI. 정답 경로를 사용하지 않는 강화학습과 10×10 게임 보드,
가중치 heatmap, 해결 성공률 및 보상 그래프를 제공합니다. GitHub에는 자동 업로드하지 않습니다.

## 실행

Python 3.11 또는 3.12에서 프로젝트 폴더로 이동한 다음 실행합니다.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python main.py
```

NumPy + PySide6의 CPU 구현입니다. 다음 실행에는 가상환경 활성화 후 `python main.py`만 필요합니다.
Apple Silicon/Intel Mac의 실제 실행은 사용자 환경에서 확인해야 합니다.

## 사용 방법

1. `APK 가져오기`에서 보유한 APK를 선택합니다. APK를 실행하지 않고 초기 배치만 읽습니다.
   경로는 `data/preferences.json`에 저장하여 다음 실행에 다시 불러옵니다.
2. `강화학습`을 누르면 무작위 초기 가중치에서 확률적으로 합법 행동을 선택하며 학습합니다.
   이미 학습한 모델이 있다면 그 가중치와 optimizer 상태에서 계속 학습합니다.
3. 현재 페이지의 학습 문제만 먼저 탐험하며 검증 문제는 초기 배치에서 대기합니다.
   학습 단계가 끝나면 모델을 고정하고 검증 문제만 greedy로 실행합니다. 학습 문제의 결과는 그대로 남습니다. 반복 배치에서도 즉시 중단하지 않고 최대 300수까지 시도합니다.
4. 한 epoch는 버튼을 누른 시점의 현재 화면에서 학습 문제 각각 한 번의 episode입니다.
   다른 페이지의 문제는 학습하거나 평가하지 않습니다. 번호 옆에 [학습]/[검증]을 항상 표시합니다.
   페이지를 바꿔도 topology 기반 소속은 유지됩니다. 검증 전용 화면에서는 학습을 시작하지 않습니다.
5. `신경망 추론`은 현재 페이지에서 가장 확률이 높은 합법 행동을 선택하는 greedy 추론입니다.
   이때는 반복 상태 또는 300수 한도에서 종료합니다. 재생 간격 설정은 이 추론 애니메이션에 적용됩니다.
6. 보드를 클릭하면 확대 화면, 행동 확률 및 예상 할인 누적 보상(value)을 확인합니다.
7. `저장`/`불러오기`는 v2 NPZ 모델과 Adam 상태를 보존합니다. 과거 지도학습 v1 파일은 거부합니다.
   프로그램 시작 시 가중치는 자동 로드하지 않습니다. 그래프 이력과 탐험 RNG 상태는 저장하지 않으므로
   재시작 후 완전히 동일한 학습 궤적을 재현하는 checkpoint는 아닙니다.

학습 중 현재 페이지는 약 30ms 간격으로 상태를 전달하며 16 step마다 가중치를 갱신합니다.
가중치 heatmap은 epoch 종료 시 갱신합니다. `정지`하면 완료된 업데이트를 유지합니다.
참조해 재생 기능은 제거했습니다. APK 참조 수순은 학습/평가에 사용하지 않으며 가져온
Puzzle의 solution은 모두 비어 있습니다.

## 강화학습 방식

동기식 n-step Advantage Actor–Critic(A2C), n=16, discount gamma=0.99입니다.
Actor는 합법 행동을 확률적으로 선택하고 critic은 앞으로 받을 할인 누적 보상을 추정합니다.
실제 보상과 critic의 추정치를 이용해 정책을 갱신하며 정답 행동 라벨은 만들지 않습니다.

| 결과 | 보상 |
| --- | --- |
| 출구 통과 | +1.00 |
| 일반 이동 | −0.01 |
| 해당 episode에서 이미 방문한 배치로 이동 | −0.04 (이동 −0.01 및 추가 −0.03) |

300수 제한을 유한 episode의 종료로 취급합니다. 종료 상태는 bootstrap하지 않습니다.
정답 경로나 최단 거리 기반 보상은 없습니다. 퍼즐 규칙, 성공 판정, 위 보상 규칙은 환경에 정의되어 있습니다.
엔트로피 계수 0.02, critic Huber loss 계수 0.5, Adam learning rate 0.0003,
global gradient norm clip 1.0을 사용합니다. 탐험 RNG는 각 학습 실행에서 seed 42로 시작합니다.

## 그래프와 검증

- 해결 성공률: 학습 곡선은 해당 epoch 화면의 확률적 학습 탐험에서 성공한 비율이고,
  검증 곡선은 뒤이어 고정된 모델로 수행한 greedy 검증의 성공 비율입니다.
  두 곡선은 행동 선택 방식 및 업데이트 여부가 달라 동일 조건 성능 비교가 아닙니다.
  화면과 그래프의 성공 개수는 일치하며, 그래프는 두 단계가 모두 끝나야 갱신합니다.
  중간에 정지하면 미완료 epoch는 기록하지 않습니다. 검증 문제가 없으면 검증 곡선은 표시하지 않습니다.
- 보상: 해당 epoch의 현재 화면 학습 episode에서 얻은 할인하지 않은 누적 보상의 평균입니다.
  정답 라벨이 없으므로 행동 정확도 그래프를 이 그래프로 대체했습니다.
- 두 그래프 모두 심볼과 면적 채움 없는 꺾은선입니다. 첫 epoch는 수치만 보이고 두 번째부터 선이 생깁니다.
- 차량 방향/길이/lane/목표 topology로 약 80/20 그룹 분할합니다. 동일 topology의 파생 배치는
  분할을 넘지 않습니다. 해당 APK 전체 소속은 학습 2,034개, 검증 466개지만 실제 학습은 현재 페이지로 제한합니다.
- VAL 경험은 gradient와 value target에 포함하지 않습니다. 검증 집합은 개발용이며 독립 test set은 아닙니다.
- `runs/rl-*.jsonl`에 epoch별 지표와 보상 설정을 기록합니다. 새 학습 실행은 새 그래프와 로그로 시작합니다.

## 모델 및 연구 범위

224 입력 = 최대 14대 × 16특성(존재/목표/수평/길이3 및 lane/위치 one-hot).
목표 X를 첫 슬롯에 두고 나머지는 label 순입니다. 140행동 = 14대 × 2방향 × 거리 1~5.
MLP 224→128→64→141이며 마지막 출력은 policy 140개와 value 1개입니다.
가중치 45,888개, bias 333개이며 두 은닉층은 ReLU입니다.

처음부터 보상만으로 학습하므로 초기 실패가 많고, 장기 문제에서는 탈출 보상이 희소하여
학습이 정체될 수 있습니다. 현재 버전의 장기 성능 향상은 확인하지 않았습니다.
BFS 정답 생성, DAgger, 지도학습 사전학습, 탐색 fallback은 GUI 강화학습에 사용하지 않습니다.
이전 지도학습 관련 모델 유틸리티는 테스트 호환용으로 남아 있으나 RL worker가 호출하지 않습니다.
NAND 연동, 양자화, 소자 잡음, 에너지 측정, GPU 가속은 구현하지 않았습니다.

- 보상 정의가 바뀌었으므로 이전 버전의 보상 그래프와 직접 비교하지 마세요.

## v0.2.7 — 학습 탐험 후 전체 greedy 평가

각 epoch는 두 단계로 진행됩니다.
1. 현재 페이지의 학습 문제만 확률적 탐험으로 가중치를 갱신. 검증 문제는 대기.
2. 학습 종료 가중치의 고정 복사본으로 현재 페이지의 모든 문제를 초기 배치부터 greedy 평가. 학습/검증 모두 반복 배치 또는 최대 300회에서 종료. 성공 시 종료.

성공률 두 곡선은 두 번째 단계의 Train greedy / Val greedy입니다.
보상 곡선은 첫 번째 단계의 학습 탐험 평균 누적 보상입니다. 화면의 평가 보상과는 다를 수 있습니다.
로그는 탐험 성공 수와 greedy 성공 수를 별도로 보관합니다.
학습/검증의 실제 개수는 현재 페이지의 기존 분할에 따릅니다.
이 버전은 평가 조건을 일치시키며 일반화 개선 알고리즘은 추가하지 않았습니다.

## v0.2.8 — 세 그래프와 Efficiency

기존 그래프 영역의 폭을 세 그래프가 나눠 사용합니다. 가중치 영역과 상단 높이는 유지합니다.
- Solve success: Train explore / Train greedy / Val greedy 세 꺾은선.
- RL episode reward: 학습 탐험 평균 누적 보상.
- Efficiency: epoch 종료 greedy 평가의 현재 페이지 전체 평균. 성공 시 Minimum possible / actual moves, 실패 시 0. actual moves는 자동 탈출 비용까지 포함한 화면 이동 칸 수.
- 정상 기준 범위는 0~1이며 실패를 포함하므로 평균은 0일 수 있습니다. 기준보다 짧은 성공으로 1을 넘는 경우는 임의로 자르지 않고 원비율을 기록합니다. 필요 시 축이 확장됩니다.
- 로그에 문제 순서별 actual moves, Efficiency, 원비율 및 1 초과 개수를 저장합니다.
- 기준값이 없는 성공 문제는 평균을 해당 없음으로 표시합니다. APK 2,500개는 기준값이 있습니다.
- 기존 선만 표시하는 스타일 유지. 학습 알고리즘과 보상은 변경하지 않았습니다.

## v0.2.9 — epsilon-greedy

학습 행동은 확률 epsilon으로 합법적인 행동 중 균등 무작위 선택, 나머지는 최고 정책 점수 행동 선택입니다. 무작위 분기에서도 최고 점수 행동이 선택될 수 있습니다.
실행 시작 epsilon=1.00, 설정 epoch의 앞 80% 동안 선형으로 0.05까지 감소, 이후 유지. 300 epoch이면 epoch 1=1.00, epoch 240~300=0.05. 1 epoch 실행은 1.00입니다. 새 학습 실행마다 스케줄은 리셋하며 checkpoint 재개 시에도 새 스케줄입니다. UI와 epoch 로그에 epsilon을 기록합니다.
평가는 epsilon=0, 최고 점수 행동 선택, 반복 배치 종료. 학습/검증 경험 분리 유지.

기존 on-policy A2C에 행동 선택만 바꾸지 않고 V-trace 보정을 적용했습니다. 최대 16-step chunk 동안 수집한 행동에 mu(a|s)=epsilon/N+(1-epsilon)I(a=argmax)를 기록합니다. target policy는 기존 masked softmax, rho와 c는 min(1,pi/mu), gamma=0.99. V-trace 가치 표적과 rho*(r+gamma*v_next-V) 정책 advantage를 사용합니다. 엔트로피 계수 0.02 유지. gradient clipping 및 Adam 유지. 클리핑은 분산을 제한하지만 편향이 있으며 개선을 보장하지 않습니다.
참고: https://proceedings.mlr.press/v80/espeholt18a.html

이전 RL checkpoint의 네트워크 형태는 같아 로드할 수 있지만 epsilon 진행 상태는 저장되지 않습니다. 정답 수순이나 Minimum possible을 학습 표적으로 사용하지 않습니다.
장기 해결률 향상은 아직 검증하지 않았습니다.
